# Сетевой сервер

Курсовая работа по дисциплине «Технологии и методы программирования».

Сервер на C++17 для Linux. Принимает по TCP векторы беззнаковых 16-битных чисел и возвращает сумму квадратов элементов. Если сумма превышает 65535, возвращается 65535. Клиенты обслуживаются последовательно в одном потоке. Для аутентификации используется SHA-1 с солью, сформированной клиентом.

## Сборка и запуск

Для сборки нужны компилятор с поддержкой C++17 и make.

```bash
make
cp clients.conf.example clients.conf
./build/server --run
```

В файле `clients.conf` каждая строка содержит логин и пароль через двоеточие:

```text
user:P@ssW0rd
```

База загружается при запуске сервера. Ошибки записываются в `server.log`. Остановка сервера - Ctrl+C. Таймаут приема/передачи клиента составляет 180 секунд.

## Параметры

```bash
./build/server -b clients.conf -l server.log -p 33333
```

- `-b` - путь к базе пользователей, по умолчанию `./clients.conf`.
- `-l` - путь к журналу, по умолчанию `./server.log`.
- `-p` - TCP-порт, по умолчанию `33333`.
- `--run` - запуск с настройками по умолчанию.
- `-h` - справка. Без аргументов также выводится справка.

## Файлы

- `src/server.cpp` - запуск сервера, обработка подключений и журнал ошибок.
- `src/core.cpp`, `src/core.h` - чтение базы, аутентификация и расчёт суммы квадратов.
- `src/net.h` - работа с сокетами и передача данных.
- `src/logger.h` - класс журнала ошибок, вынесенный для отдельного тестирования.
- `Makefile` - сборка программы.

## Обмен данными

Сообщение аутентификации: `LOGIN || SALT16 || HASH40` без перевода строки. Хеш вычисляется как `SHA1(SALT16 || PASSWORD)`. Соль и хеш записываются шестнадцатеричными цифрами в верхнем регистре. Ответ сервера - `OK` или `ERR`.

После успешного входа используется бинарный формат и порядок байтов little-endian. Клиент передаёт число векторов `uint32_t`. В ответ сервер передаёт количество результатов `uint32_t` (то же значение N). Затем для каждого вектора клиент отправляет его размер `uint32_t` и элементы `uint16_t`, а сервер возвращает результат `uint16_t`. **Клиент должен прочитать 4 байта количества результатов сразу после передачи N, до передачи первого вектора.**

Эти правила задают порядок байтов, границы текстовых сообщений и порядок ответов, которые не полностью определены в задании.

## Модульное тестирование (этап сдачи)

Модульные тесты реализованы на C++17 с применением `assert` в файле
`tests/test_modules.cpp`. Для запуска:

```bash
make test
```

Команда `make check` в данном комплекте выполняет **только модульные тесты**.
Успешный запуск должен завершаться строкой:

```text
TOTAL 47 PASSED 47 FAILED 0
```

Тесты компилируются с `-UNDEBUG`, поэтому проверки `assert` не отключаются.

## Важные ограничения протокола

* Сервер принимает целиком текстовое сообщение без разделителя и определяет его
  окончание по логинам из базы и фиксированным размерам соли и хеша. Поэтому
  клиент не должен добавлять перевод строки или бинарный заголовок перед ним.
  Максимальная длина логина в этой реализации — 128 байт.
* Формат чисел — **little-endian**; его необходимо согласовать с клиентом
  преподавателя, поскольку в задании порядок байтов не уточнен.
* Для защиты памяти установлены локальные ограничения: максимум 10000 векторов
  за сеанс, 1000000 значений в одном векторе и 10000000 значений за сеанс.
